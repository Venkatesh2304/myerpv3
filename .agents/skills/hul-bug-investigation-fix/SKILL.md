## 2. Fast Diagnostic Triage Checklist

### Vector A: External Authentication Failures
- **IKEA (Leveredge)**:
  - Check `client.is_logged_in()`:
    ```bash
    python3 -c "from custom.classes import Ikea; print(Ikea('devaki_urban').is_logged_in())"
    ```
  - **Rule**: If `False`, **DO NOT code automated login in views**. The backend cannot solve IKEA Recaptcha directly. Session cookies must be pushed via `/ikea_login` or generated by the AWS ECS Fargate task triggered via `/trigger_ikea_login`.
- **GST / NIC E-Invoice Portals**:
  - **CRITICAL LOCKOUT RULE**: Entering wrong credentials or failed captchas $\ge 5$ times (`SWEB_9014`) locks the distributor's government tax account or bans the server IP.
  - Check captcha flow via `/custom/captcha` $\rightarrow$ `/custom/login`.
- **Unilever SAP**:
  - Check if the Redis worker is alive: `redis-cli ping`.
  - Check `redis_worker.service`: `sudo systemctl status redis_worker.service`.

### Vector B: Upstream Portal State & Contract Breakages
- **Error: `"Screen Already Exists"` (IKEA)**:
  - Cause: A previous request died without removing the screen name from the session.
  - Fix: Ensure the method is wrapped with [`@ikea_screen("Screen Name")`](file:///home/ubuntu/myerpv3/custom/classes.py#L47). The decorator calls `/removeScreenNameFromSession` and retries.
- **Error: `StatusCodeError` or `ReportFetchError`**:
  - Inspect `logs/<key>/<user>/debug.log`. `StatusCodeError` dumps the full executed cURL with headers and response text.
  - If upstream changed form parameters, capture a fresh cURL from browser DevTools, update `custom/curl/<key>.txt`, and run `interpret_all_curls()`.

### Vector C: Concurrency & Mutex Deadlocks
- **Error: `"Process ongoing"` or Billing Stalled**:
  - Check [`Billing.ongoing`](file:///home/ubuntu/myerpv3/bill/models.py#L15) and [`Billing.stop`](file:///home/ubuntu/myerpv3/bill/models.py#L14).
  - Stale locks expire automatically after 15 minutes (`BILLING_LOCK_TIMEOUT = 900`).
  - To manually reset a hung billing lock:
    ```python
    from bill.models import Billing; Billing.objects.filter(company_id="devaki_urban", date=today).update(ongoing=False)
    ```
- **Error: `"Data mismatch (Hash invalid)"`**:
  - The client submitted an outdated MD5 hash. Line items were modified or re-fetched. Client must refresh order state.

### Vector D: Data Discrepancies & Unexpected Deletions
- **Missing Bills after Sync**:
  - Check [`Bill.sync_with_salesregister`](file:///home/ubuntu/myerpv3/bill/models.py#L87). Deletion of cancelled bills is blocked if missing count $\ge 10$ to prevent data loss during upstream timeouts.
- **Manual Edits Reverted after Ingestion**:
  - Check [`SalesChanges`](file:///home/ubuntu/myerpv3/erp/models.py#L156). Changes must be applied using `sales.update_and_log(field, new_val, notes)`. The `GstFilingImport` pipeline replays `SalesChanges` post-import.

## 3. Forensic Log Locations

| Component | Log Path | What to Look For |
| :--- | :--- | :--- |
| API Audit & Failures | `core.models.ApiRequestLog` | Full request body, response body, query params, and Python tracebacks for failed endpoints (`status_code >= 400`). |
| External HTTP Scrapers | `logs/<key>/<user>/debug.log` | Raw HTTP status codes, response elapsed times, cURL command dumps. |
| Operational Events | `logs/<key>/<user>/info.log` | High-level business milestones (order counts, bills processed). |
| Database Queries | `sql.log` | Slow unindexed queries, table locks, foreign key constraint violations. |
| Gunicorn Backend | `journalctl -u backend.service -n 100` | Uncaught Django exceptions, WSGI worker restarts, OOM kills. |
| Redis Workers | `journalctl -u redis_worker.service -n 100` | SAP Selenium worker crashes, Redis queue timeouts. |

### Inspecting Recent API Failures
Run this targeted one-liner to get immediate forensic context on any failed request:
```bash
python3 -c "
from core.models import ApiRequestLog
for r in ApiRequestLog.objects.filter(is_error=True).order_by('-timestamp')[:3]:
    print('='*50)
    print(f'{r.timestamp} | {r.method} {r.path} | Status: {r.status_code} | User: {r.user} | Company: {r.company}')
    if r.query_params: print(f'Params: {r.query_params}')
    if r.request_body: print(f'Body: {r.request_body[:300]}')
    if r.response_body: print(f'Response: {r.response_body[:300]}')
    if r.error_traceback: print(f'Traceback:\n{r.error_traceback[:600]}')
"
```

## 4. Verification & Testing Rules

1. **Test Minimally on Shell**: Test the patched function directly in a targeted Python one-liner without spinning up a browser.
2. **Preserve Memory Discipline**: Never run test queries that fetch thousands of rows into memory without `.filter()` or `.values()`.
3. **Verify Upstream Idempotency**: Ensure database updates inside `transaction.atomic()` roll back cleanly on failure.
